# settings/v1

The settings an app's own superusers change for its extensions (PITR's S3 bucket, Bulk Mail's sending limits), behind
one API: list them, read one, save one, test one without saving. Each extension keeps its settings its own way and
registers a section; the provider serves them all. Settings an operator sets for a whole host stay in
`pocketone.yaml`.

A wire contract ([settings.go](settings.go)).

## Use

| Operation | HTTP | Token scope |
|---|---|---|
| List | `GET /api/_c/settings/v1` | `settings:read` |
| Get | `GET /api/_c/settings/v1/get?extension=pitr` | `settings:read` |
| Save | `POST /api/_c/settings/v1/save` with `{"extension": "pitr", "values": {...}}` | `settings` |
| Test | `POST /api/_c/settings/v1/test` with `{"extension": "pitr", "values": {...}}` | `settings` |

Each extension's `values` are its own shape (see its README). Secrets come back empty with a flag that they're set;
saving an empty secret keeps the saved one. `Test` answers `{"ok": false, "message": ...}` when the settings don't
work. Only superusers may call any of them.

## Provide

**An extension with settings** registers a section in its `Register`:

```go
settingsv1.Add(app, mySection{}) // Info, Get, Save; Test too if the settings can be checked
```

and declares `WorksWith: extkit.IDs("settings/v1")`.

**A provider of the API** (ext/settings by default) implements `settingsv1.Settings` over
`settingsv1.Sections(app)`.
