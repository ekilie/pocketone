# api-tokens.verify/v1

Another server checks one of an app's API tokens. A host in front of an app's accounts (a PocketHost edge in front of
the mothership) is handed a token by a client and asks the app that issued it who the token acts as and what it may
do. Companion to [api-tokens/v1](../../v1/README.md): whatever provides that provides this.

A wire contract ([verify.go](verify.go)).

## Use

| Operation | HTTP | Who |
|---|---|---|
| Verify | `POST /api/_c/api-tokens.verify/v1` `{"token", "ip"}` | superusers (`api_tokens_verify`) |

`ip` is the client's address, recorded as the token's last use; leave it out to leave the last use alone.

A valid token:

```json
{"valid": true, "grant": {"tokenId": "...", "name": "ci", "ownerCollection": "users", "ownerId": "...",
  "scopes": ["instances=abc123"]}}
```

`scopes` empty means the owner's full rights; a scope with a value (`instances=abc123`) holds it for that value only
(see [api-tokens/v1](../../v1/README.md)). A token that isn't valid is an answer, not an error, so a caller can tell a
refused token from an outage: `{"valid": false, "reason": "invalid"}` (unknown, malformed or revoked) or
`"expired"`.

In Go, from the other server:

```go
c := verifyv1.NewClient("https://app.example.com", superuserToken, nil)
res, err := c.Verify(ctx, extkit.Auth{}, verifyv1.Input{Token: token, IP: ip})
if err != nil { /* the app is unreachable: don't treat the token as refused */ }
if !res.Valid { /* 401: res.Reason */ }
if !res.Grant.HasScopeFor("instances", id) { /* 403 */ }
```

Cache answers briefly if you verify on every request: a revoked token then stops working once its entry expires.

## Provide

Implement `verifyv1.Verifier` over the same tokens as your `api-tokens/v1` provider. Never return an error for a
token that isn't valid: return `Valid: false` and a reason.
