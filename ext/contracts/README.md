# Contracts

Every API a PocketOne extension offers is a contract: a versioned Go interface, and the HTTP API, hooks and MCP tools
that come with it, at `/api/_c/<id>/`. Extensions have no routes of their own. An extension says what it
**implements**, **requires** and **works with** in terms of these contracts, never another extension's name, so any
extension that implements a contract can stand in for another. PocketOne answers "who provides this contract on this
app?" at startup and prints the answer.

Every contract lives here, standard or community; extensions live in `ext/<name>`. Each contract is a package named
for its id and major version: `deploy/v1` is `github.com/pockethost/pocketone/ext/contracts/deploy/v1`,
`mail.fallback/v1` is `.../mail/fallback/v1`. A change to what a contract promises is a new major version (`v2`) next
to the old one.

The table is generated from each contract's README and every extension's `Contracts()`: run
`go run ./.github/extensions contracts` (CI fails when it's stale).

## Three kinds

- **Service:** a Go interface, looked up in the same process (`fallbackv1.Contract.Of(app)`).
- **Wire:** a service with an HTTP API under `/api/_c/<id>/`, generated from its interface: each method is an
  operation with its own HTTP method, path and token scope (`//op: POST restart scope=remote`); inputs and results are
  JSON, uploads (`extkit.RawIn`), downloads (`extkit.RawOut`) or streams (`extkit.Stream`, sent as server-sent
  events). It gets action hooks (`remotev1.OnRestart`, `onRemoteRestart` in `pb_hooks`), an MCP tool per JSON
  operation and a client. Every caller (HTTP, MCP, Go) passes the same scope check and hooks.
- **Routed:** a contract whose provider is an `http.Handler` serving everything under `/api/_c/<id>/` as it is, for an
  API a protocol shapes (OAuth) or an existing API moved under a contract (deploy/v1).

A multisite host can provide a wire or routed contract for its instances, so it works for instances that run stock
PocketBase.

A contract can bring its own dashboard screen (`Contract.UI(name, fsys)`): it shows on every app that provides the
contract, whichever extension does, and calls only the contract's API. restore/v1's "Restore to a moment" works this
way.

An extension that calls a contract for its own work (bulk mail checking whoever keeps the suppression list) passes
`extkit.Internal` as the auth, and can ask who provides it with `Contract.Provider(app)`.

## Add a contract

A contract is a folder `ext/contracts/<id path>/vN/` (`mail.fallback/v1` → `mail/fallback/v1/`) with:

- the Go package: the interface, its `//contract:` directives and `zz_contract.go`;
- a `README.md`, its page on pocketone.dev, with front matter and four sections in this order:

  ```markdown
  ---
  owners: ["@your-github-handle"]
  summary: "One line: what the contract promises."
  ---

  # mail.fallback/v1

  ## Use        how to call it: HTTP, Go, pb_hooks, MCP, CLI
  ## Provide    how to implement it
  ## Extensions (generated: who provides, requires and works with it)
  ## License    MIT
  ```

Whoever first creates a contract owns it; an extension author who adds one owns both the contract and the extension
that provides it. Ids are unique across PocketOne. Pick a name for what the contract does (`restore/v1`), not for the
extension that first provides it.

## Write the interface

A contract is an interface with `//contract:` directives; [`contractgen`](cmd/contractgen/main.go) writes the rest
(`zz_contract.go`) with `go generate ./...`. A test fails when a generated file is stale.

```go
//go:generate go run github.com/pockethost/pocketone/ext/contracts/cmd/contractgen

// Deployer sends a project's code to an app.
//
//contract:id deploy/v1
//contract:kind wire
//contract:scope deploy
//contract:host
//contract:js hooks
type Deployer interface {
	// Upload writes changed files to the app.
	Upload(ctx context.Context, a extkit.Auth, in UploadInput) (UploadResult, error)
}
```

Methods take `ctx`, then (wire) `extkit.Auth`, then at most one input; they return `error` or one value and `error`.
The doc comment of a wire method is its MCP tool's description. Contracts are reviewed like PocketOne's core: a
contract is a promise every implementation keeps.

## Use one

```go
// provide (in Register)
deployv1.Contract.ProvideDefault(app, myDeployer{})

// consume (after registration: in hooks, at serve time)
d := deployv1.Contract.Must(app)

// declare it, so PocketOne can order and switch extensions
func (e *Extension) Contracts() extkit.Contracts {
	return extkit.Contracts{Implements: extkit.IDs("deploy/v1"), Defaults: extkit.IDs("deploy/v1")}
}
```

Choose between providers in `pocketone.yaml`:

```yaml
providers:
  mail.fallback/v1: mailrelay
```
