# mail.suppression/v1

The addresses an app must not send bulk mail to (unsubscribed, bounced, complained, added by hand), and the
unsubscribe link in every bulk message. Anything that mails many people checks it.

A wire contract ([suppression.go](suppression.go)).

## Use

| Operation | HTTP | Who |
|---|---|---|
| Check | `GET /api/_c/mail.suppression/v1/check?email=` | superusers (`suppression:read`) |
| Suppress | `POST /api/_c/mail.suppression/v1/suppress` `{"email", "reason", "source", "campaign"}` | superusers (`suppression`) |
| Unsuppress | `POST /api/_c/mail.suppression/v1/unsuppress` `{"email"}` | superusers (`suppression`) |
| UnsubscribePage | `GET /api/_c/mail.suppression/v1/unsubscribe?t=<signed token>` | public: the link in a message |
| Unsubscribe | `POST /api/_c/mail.suppression/v1/unsubscribe` | public: the page's form, or a mail provider's one-click POST |

Reasons: `unsubscribed`, `bounced`, `complained`, `manual`. The page never unsubscribes on a `GET` (link scanners
open every URL in a message); one-click unsubscribes follow RFC 8058 (`List-Unsubscribe=One-Click`). The token is
signed by the provider, so only links it issued work.

## Provide

Implement `suppressionv1.List`; sign the tokens in the links your messages carry, and point `List-Unsubscribe`
at `/api/_c/mail.suppression/v1/unsubscribe?t=...`.
